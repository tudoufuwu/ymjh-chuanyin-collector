# 负责地使用与公网绑定

## 只读采集边界

采集器设计为 Windows 本地只读工具：它通过进程查询与内存读取 API 获取结构化聊天事件。它不应被用于写入内存、注入代码、绕过认证、获取账号/会话资料或检查你无权访问的软件。

请仅对你拥有或明确获授权检查的软件和数据运行它，并自行遵守相关法律、平台条款和隐私要求。

## 默认本地地址

网页默认只监听：

```text
http://127.0.0.1:8766
```

这是推荐设置。只要保持本地监听，程序不会自行对公网开放任何内容。

## 使用你自己的公网域名或 Tunnel

本项目**没有内置网页认证**。如果将聊天网页暴露到公网，部署者必须先在外层配置 HTTPS、身份认证和访问策略。不要把真实域名、Tunnel ID、Token、证书或密码提交到 Git。

### 方式一：反向代理

让反向代理监听你的域名，并将认证后的请求转发到：

```text
http://127.0.0.1:8766
```

保持本程序使用默认 `--host 127.0.0.1`。认证、TLS 证书、允许访问的用户和防火墙规则由你的反向代理负责。

### 方式二：自己的 Cloudflare Tunnel

在已安装并登录你本人 Cloudflare 账户的电脑上，Tunnel 的后端服务仍指向本机：

```text
http://127.0.0.1:8766
```

通用思路：

1. 在你的 Cloudflare 账户内创建一个 Tunnel；
2. 在账户内为自己的域名配置 DNS 路由；
3. 配置 Tunnel 的 ingress 服务为 `http://127.0.0.1:8766`；
4. 使用 Cloudflare Access 或等价认证策略，仅允许你指定的身份访问；
5. 将 Tunnel Token、UUID、证书、配置文件和域名保留在本机安全位置，不要放进本仓库。

临时命令示例（仅用于你自己的受控测试环境）：

```powershell
cloudflared tunnel --url http://127.0.0.1:8766
```

临时 URL 没有替代访问控制；它不适合真实聊天数据。持久部署前必须先配置身份认证和访问限制。
